# 9FBG 0.7.1

独立的九光栅原始光谱采集、固定身份跟踪和诊断程序。源码开发版，使用独立 `.venv`，不导入 TOUCH 后端。界面与设备读取分离，刷新页面不会重启设备。

## 从 GitHub 下载并启动

Windows 上先安装 Python 并确保 `python` 命令可用。本机验证环境为 Python 3.14.1 64 位；锁定的 NumPy/SciPy 依赖要求 Python 3.12 或更高版本。

```powershell
git clone https://github.com/lincake/9FBG.git
cd 9FBG
.\9FBG-Setup.cmd
.\9FBG-Dev.cmd
```

`9FBG-Setup.cmd` 仅在首次配置或显式更新时创建独立 `.venv` 并安装 `requirements.txt` 中的依赖。日常使用 `9FBG-Dev.cmd`，浏览器地址为 `http://127.0.0.1:9769/`；启动不安装、测试、打包或自动连接设备。新机器上的启动不依赖本机 `C:/光纤触觉/9FBG.lnk` 快捷方式。

实际光谱硬件还需厂商 USB 驱动及 .NET Framework 4 运行支持。仓库保留 x86 SDK helper、厂商 DLL、512 点实际标定轴、原始标定 CSV 与来源哈希清单。随附波长轴来自 F1520808 标定导出，PX6D 配置保留当前硬件身份绑定；实际光谱设备与此标定文件的对应关系仍须核实。更换设备须重新核对 `config/device.json` 与对应标定，不能套用旧设备的轴。安装脚本不安装硬件驱动。

采集数据、训练模型、用户设置和本机验收证据存放于 `userdata/`、`evidence/`，不随源码上传；本机原件继续保留。历史版本说明中的本地证据路径仅用于本机追溯。可选运行 `9FBG-Test.cmd` 检查 Python 测试；前端测试另需 Node.js，运行 `node --test tests/test_frontend.mjs tests/test_display.mjs tests/test_experiment.mjs tests/test_preferences.mjs`。Node.js 不参与正常启动。

## 0.7.0 全部采集记录、可恢复删除与多条联合训练

“② 训练”中的“采集数据与历史记录”默认列出全部采集会话，包括无合格轮次、诊断和未完整保存的记录。每条显示原始采集北京时间（精确到分钟）、数据编号、样件、各点尝试/合格轮数、唯一会话编号和完整路径，并标明训练资格。点击“打开保存位置”在资源管理器打开该记录目录。

可勾选一条或多条记录，使用全选可训练数据、清空选择和批量训练。加权最小二乘、小型 MLP 均支持联合训练；所选记录须为完整 A/B 会话，样件、点位与力方向、装夹及温度条件、光谱算法/配置一致。每点的合格完整轮次可跨所选记录合计，仍须至少三轮；训练范围是这些记录实际采到的点位。不可训练或不兼容项明确报错，不静默排除。训练进度按每份原始数据实际校验和补算、训练、保存推进；模型保存全部来源并可在实机验证选择，训练不切换当前模型或改变实机人工统计。

“删除所选”先显示将移动的逐条数据时间、编号与路径，确认后整批移入 `userdata/deleted_calibration_sessions/`。这不是永久销毁：勾选“查看已删除”后可以打开其位置、选择并恢复至原目录。操作日志位于 `userdata/history_operations/`。训练、采集或保存进行中禁止删除/恢复，批量预检不通过则不移动；移动或操作日志保存失败会尝试整批回退，绝不覆盖同名目录。历史模型仍可核验回收区中的原始来源；回收区记录必须恢复后才能重新训练。

联合训练按完整试次及其无载基线分折，不随机拆相邻帧；同一真实目录的大小写别名不能重复计作多个训练来源。内部整轮检查不代表跨天/跨装夹独立泛化，也不用于界面实机正确率。实机验证继续只汇总实际保存的人工按压判断。

## 0.6.0 采集、训练、实机验证

当前界面只保留三个工作区。左侧仅有设备连接，移除“参考与按压”、本地回放和离线评估入口；首次无载标定仍在最前面。原始会话、历史模型、历史报告与旧设置文件保留，不改写。

1. **采集**：沿用点位确认、每轮手动无载标定、加载约 3 N、卸载与质量判定的流程。会话列表显示采集北京时间（精确到分钟）、数据编号及逐点合格轮数。
2. **训练**：选择一个已保存的 A/B 会话，选择“加权最小二乘”或“小型 MLP”，点击“开始训练”。已采四点各三轮的数据可用于两种模型。进度来自实际文件校验、原始光谱补算、分轮训练检查、训练迭代和模型保存；失败保留实际进度和原因。成功后显示模型编号、方法、时间及训练点位，并在实机模型选择中选中它，需手动载入。此操作不自动切换当前模型或改变设备、零点、参考。
3. **实机验证**：选择并载入刚训练或历史模型，建立本次无载参考；选择目标点再实际按压，看识别绿灯、预测力、同步 PX6D 力和差值。分别人工勾选位置正确、力正确（差值 ≤0.3 N），保存本次判断。结束时点击“结束验证并查看结果”，显示本轮保存次数、位置/力/同时正确率、有效力误差 MAE/RMSE 和拒识次数。没有保存判断时不生成正确率；尚有待保存判断时先处理再结束。

结束结果独立保存到 `userdata/validation_sessions/<会话编号>/report.json`，对应逐事件哈希链 `records.jsonl`。刷新或重启后可恢复报告；继续实际判断自动开始新一轮，不把上一轮计入本轮结果。拒识作为人工保存的失败计入分母，没有有效预测力则不计入力误差均值。模型输入只有九路 FBG 漂移，目标选择与 PX6D 对照不进入推断。

小型 MLP 使用 NumPy，网络为九维输入、32/16 隐层、已采集点位分类及按压力输出；归一化、范围和拒识阈值由训练轮确定。两种方法均按完整试次及其基线隔离检查，再以全部合格轮拟合保存。内部训练检查文件用于可追溯性，界面不再展示离线评估分数。四点模型只识别采过的四点，不代表其余 21 点或完整物理精度验收。

当前稳定入口为 **0.6.0 源码开发版** `C:/光纤触觉/9FBG.lnk`。启动不安装、测试、打包或自动连接设备，上次连接参数、数据编号等设置继续保留。下面保留旧版行为记录，仅作历史说明。

## 0.5.1 点击目标并直接按压验证

“③ 实机验证”支持载入已保存的少量点研究模型或完整 25 点模型，明确显示模型训练过的点位。P01、P05、P21、P25 四点模型只在这四点之间识别，其余 21 点标记未训练。5×5 矩阵左下为 P01（行 0、列 0），向右为 +x，向上为 +y/指尖；灯光只由当前有效模型预测决定，实际点位选择和人工勾选不输入模型。

1. 连接光谱与 PX6D，载入模型，核对样件、装夹及力方向；移开接触棒，明确确认无载并建立本次实机验证参考。新参考建立后冻结，模型更换、重连、参考改变或数据过期需要重新确认。
2. 点击 5×5 矩阵里的目标点，再按压手指上的对应位置。目标有独立边框，模型识别点亮绿灯；直接查看位置是否一致、模型预测力、同一光谱时刻的 PX6D 按压力与两者差值。目标与 PX6D 均仅用于对照，预测输入始终为九路波长漂移。
3. 不需单独点击冻结按钮。要记录结果时，分别手动勾选“位置正确”和“力正确（误差 ≤0.3 N）”，首次勾选自动保留当时读数和目标，之后可卸载再保存。两个均不勾可直接保存失败。
4. 点击“保存本次判断”后计入实机统计。重新判断可开始下一次；待保存时禁止换目标，后端禁止更改当时目标、把位置矛盾标正确或把超过 0.3 N 的差值标记为力正确。服务端保留模型、九维输入、预测、同步原始六轴帧、零点、算法/配置/参考及时间身份，重启可恢复。
5. 查看该模型的人工判定总数、位置正确率、力正确率和同时正确率。没有保存判定时显示尚未实机验证；离线交叉验证结果不加入这些计数。

有效采集与同步条件下的模型拒识可以冻结并保存失败，计入实机分母；光谱/六轴陈旧、不同采集时段或同步失效时不允许保存验收。拒识结果没有有效预测力时，MAE/RMSE 留空并只对有数值的有效力预测计算，不能冒充零误差。无载状态不能保存为一次按压验收。同一冻结样本重复提交不会增加计数，放弃待判定不计分。

人工验证记录独立保存到 `userdata/validation_sessions/<会话编号>/records.jsonl`，逐事件追加并同步落盘、带哈希链，重启恢复冻结样本与分模型统计，不混入训练会话。模型研究范围与正式训练资格保持原有定义；人工小样本成功率也不自动构成完整 25 点物理精度验收。

当前稳定入口为 0.5.0 源码开发版 `C:/光纤触觉/9FBG.lnk`。启动不自动连接设备；20 μs、25 Hz 及数据编号等上次设置继续保留。

## 0.4.2 显式高分辨率等待与后台运行验证

0.4.1 的无载诊断通过后，操作员实际会话仍出现两路节拍同时降速。三轮九峰全部有效、力值在无载范围内，但光谱辅助进程接收节拍约 15.6 ms、六轴约 34 Hz，同步因此反复失败。这说明前一版有限时段验证不足以保证其他运行状态。

Windows 11 在进程窗口不可见时不保证 `timeBeginPeriod` 请求的计时精度。0.4.2 在光谱辅助进程以及 Python 采集短等待中使用显式高分辨率 waitable timer，并保留停止响应、句柄关闭、失败原因及原有成对计时释放；不靠长时间忙循环保持节拍。后台可读的 `acquisition_timing` 诊断报告实际等待后端。

界面快照按参考版本缓存参考历史，避免每次刷新完整导出跟踪器；JSON 清洗移到采集锁外。参考状态与已发布结果按一致锁序复制，参考版本切换时旧结果暂时显示失效，等待新参考处理结果，避免旧漂移套用新参考。设备计时诊断采用不可变快照。相同源帧的谱图与九峰表不重复重绘，六轴、阶段和时效仍按原刷新节奏更新。九峰算法、512 点实际标定轴、原始协议、曝光/触发参数、固定身份及同步门槛保持原定义。

验证包含前台与后台等待、原始双路间隔及无载预采样。该软件改动仍不能提供共同硬件时钟；配对采用主机接收时间近似插值。验证记录见 `evidence/acceptance-0.4.2.json`，不构成 3 N 加载或物理精度认证。

操作员提出降低采样率后，在相同 20 μs 曝光下完成三组无载对照。100 Hz 共 17 轮，50 Hz 与 25 Hz 各 10 轮，均通过预采样后主动中止；原始四文件哈希及行数核验通过。下表配对率与处理覆盖仅统计加载提示期间，实际全程保持无载；覆盖率表示每个原始谱是否有处理结果，包含被质量门拒绝的尾帧，不代表全部有效拟合。

| --- | --- | --- | --- |
| 100 Hz | 约 97.5 Hz | 48.52% / 45.09% | 97.02% / 96.33% |
| 50 Hz | 约 49.2 Hz | 98.71% / 96.65% | 97.91% / 95.87% |

## 0.4.1 六轴独立读取与预采样诊断

修复六轴读取线程等待光谱拟合锁的问题。引导轮次收尾改由处理线程及显式操作执行，保留处理尾帧追赶与参考冻结规则；光谱拟合耗时不会再通过该收尾操作拖住 PX6D 下一次读取。

实机进一步定位到 Windows 等待粒度导致的轮询延迟：采集读取线程存活期间，Python 采集进程显式请求 1 ms 计时精度，退出线程时成对释放，失败会记录实际状态。光谱辅助进程的计时请求不代替本进程请求；该语义依据 [Microsoft timeBeginPeriod 文档](https://learn.microsoft.com/en-us/windows/win32/api/timeapi/nf-timeapi-timebeginperiod)。启动和离线回放不请求硬件采集计时。

预采样显示服务端实际的连续有效时长（目标 500 ms）、等待时长、重置次数和具体等待原因。超过 8 秒仍未取得合格预采样会结束失败轮、保留原始记录、不计入合格次数，并要求重新确认无载、手动标定。即使没有新帧，处理线程也检查超时；页面刷新和前端时钟不会推进采集阶段。

连续无载 ±0.1 N、同步间隔 40 ms/端点距离 25 ms、加载有效率 90% 等采集条件沿用，九峰算法、实际 512 点标定轴和固定身份配置不变。100 Hz 仍为设备读取请求，实际接收率与提峰处理率分别显示，不把显示跳过的帧计作成功提峰。无载诊断不构成真实按压、定位或力精度验收。

曝光、采样请求、会话条件、每点次数、上次预选点、光谱显示范围和分析选项修改后保存到 `userdata/settings.json`，下次启动恢复。保存采用校验及原子替换；无载确认、零点、参考授权、设备连接和进行中的轮次不保存为下次运行状态，启动仍不自动连接硬件。旧会话与模型保持原有内容和定义。

## 0.3.0 手动采集接口与研究反演（兼容保留）

下列分阶段手动采集接口保留兼容；0.4.0 GUI 使用上面的引导流程，分析与独立测试原则沿用。

保留光谱、九峰与六轴显示，新增“25 点标定与独立测试”工作区。连接仍默认仅显示；只有明确点击“建立记录会话”才创建 `userdata/calibration_sessions/` 下的新会话，不会自动开始真实按压或训练。

1. 接好光谱与 PX6D，按现有无载流程取得稳定的 9 峰。输入真实样件标识、批次 A/B/C、压头尺寸及固定条件，核对 25 点编号和方向。当前采用行列和归一化坐标，无毫米误差声明。
2. 操作员已确认压入时 PX6D Fz 更负；默认标签为 `F_press = −(Fz−Fz₀)`。原始六轴值及负号完整保留。安装或方向改变后应重新确认。
3. 选 P01～P25，每次独立按压前明确无接触并建立新基线。九峰稳定参考与服务端六轴 12 个不同帧、至少 400 ms 的中位数零点同时就绪后，才能开始试次。
4. 依次标记无接触预采样、加载、保持、移开、恢复、完成；建议预采样约 1～2 秒、缓慢加载约 3～5 秒、保持约 0.5～1 秒。加载与保持时冻结基线。有效且在空载噪声范围内的预采样用于无点位的噪声统计，原始阶段保留；非零接触预采样不冒充无载。中止或人工异常会排除整次试次，不删除原始文件。0～3 N 为初始方案，先逐步检查 0.5、1、2 N 响应和回零，未声明结构承载上限。
5. 结束会话后选择数据，先做少量点的诊断分析，查看九路波长漂移—力曲线、逐试次叠加、灵敏度、残差与保持状态。中心及四角试采不要求先凑齐 25 点。
6. 建模只选择 A+B 会话：A 组有无载和全部 25 点按压，B 组有无载及按压用于选择拒识阈值。线性加权最小二乘为默认主方法，同时可比较分段曲线及固定种子 `9→64→32→25 类＋1 路力` MLP。C 批不能提交建模，只在明确执行独立评估时使用。
7. A/B/C 以完整会话和试次隔离，A 拟合统计和模型，B 选阈值，C 独立评估；不逐帧随机拆分。报告包含已知点估力、联合估力、混淆、按力箱和会话统计、拒识比例及格距误差。该原则与 [scikit-learn 分组交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)一致。
8. 载入研究模型后，核对界面显示的模型样件及力定义，再明确无接触建立本次 FBG 测试参考；旧显示参考不会自动授权独立预测，切换模型后需重建。实时预测仅输入 9 个有符号波长漂移。PX6D 仅作独立真值对照，可断开；连接时独立建立服务端测试零点。无接触、定位不确定、无效和超范围分别显示，未接受估计不输出假确定点位。评估会话及已知的实时实验定义必须与模型的样件、坐标和力方向一致。

两路原始数据、逐峰完整结果和操作事件分别记录，按采集接收时间标注身份和阶段；保留单调时钟、流时段、原始包、基线、实际配置和 SHA256。训练表另存于 `userdata/analyses/<任务>/aligned_features.jsonl`，不覆盖原始文件。

离线分析先核对原始档案哈希，再逐个处理保存的原始光谱，包括在线显示队列跳过的帧。`frozen_identity_raw_replay_v1` 恢复采集时保存的固定窗口、身份锚点、完整配置和拟合种子，沿用原始局部背景高斯算法；只使用已经确认并生效的原参考及六轴零点，不根据未来数据重新归零。不安全或缺失的恢复证据明确拒绝。PX6D 采用有界缓存配对，原始数据和在线结果均保留。大会话显示当前会话补算条数。

同步接受精确接收时刻或同一时段左右插值，间隔上限 40 ms、两端距离上限 25 ms；保留实际最近样本距离，5 ms 只作为检查目标。插值的时间差为零不能冒充物理采样同步。当前设备无共同硬件时钟。

模型为版本化 JSON，核对来源摘要、参数、算法及配置；研究模型始终 `formal_ready=false`。本版没有代替操作员采集真实按压数据，也没有训练或认证现场模型。现有正式训练门仍要求真实无载/按压同批算法比较、实测漂移范围和审阅确认，不会因点击模型按钮而绕过。

## 实际设备边界

- BaySpec USB20BS SDK 返回 512 个原始 uint16 计数，**不返回实时波长轴**。使用独立保存并校验的 F1520808 厂商实际 Sense 导出标定轴。该轴非均匀，拟合使用每个实际波长值。当前物理对应、时间语义详见 `docs/DEVICE_AUDIT.md`。
- 本程序不扣背景、不平滑原始强度。DLL 内部处理未公开。平滑只可能用于粗定位；实际拟合用原始点，背景常数由拟合估计。
- 曝光和轮询等默认配置在 `config/device.json`；值来自已有设备配置和本次实测调整，不能用截图估波长。SDK 编程请求及换算值不冒充读回。请求轮询频率、收到的主机帧率、可证实的新设备帧率分别显示；协议缺少硬件帧号，真实新帧率保持未知，数值相同不删除。
- PX6D 独立读取六路 N / N·m 原值，未自动去皮或更改厂家校准。两路都保留原始数据和主机单调接收时间，匹配只接受受限左右括帧或精确接收时刻。主机接收时间近似对齐不等于物理曝光同步。
- 高斯窗口来自实际九峰及相邻峰中点，身份固定。按压漂移预留范围在真实按压数据确认前标记“未验证”，正式训练门会拒绝。
- 设备采用共享独占租约；同一硬件不能由多个端口/进程同时打开。
