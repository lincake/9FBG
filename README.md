# 9FBG 0.21.11

独立的九光栅原始光谱采集、固定身份跟踪和诊断程序。源码开发版，使用独立 `.venv`，不导入 TOUCH 后端。0.19.0 起使用原生 PyQt6 中文桌面界面；窗口直接调用 Python 采集服务，正常运行不启动 HTTP 服务、不打开浏览器，也不依赖 WebEngine。

## 从 GitHub 下载并启动

Windows 上先安装 Python 并确保 `python` 命令可用。本机验证环境为 Python 3.14.1 64 位；锁定的 NumPy/SciPy 依赖要求 Python 3.12 或更高版本。

```powershell
git clone https://github.com/lincake/9FBG.git
cd 9FBG
.\9FBG-Setup.cmd
.\9FBG-Dev.cmd
```

`9FBG-Setup.cmd` 仅在首次配置或显式更新时创建独立 `.venv` 并安装 `requirements.txt` 中的依赖（包括 PyQt6）。日常使用 `9FBG-Dev.cmd` 打开桌面窗口；启动不安装、测试、打包或自动连接设备。本机固定快捷方式为 `C:/光纤触觉/9FBG.lnk`，新机器可直接运行启动脚本。`python -m ninefbg` 和旧的 `python -m ninefbg.server` 入口也进入同一个原生桌面程序。

实际光谱硬件还需厂商 USB 驱动及 .NET Framework 4 运行支持。仓库保留 x86 SDK helper、厂商 DLL、512 点实际标定轴、原始标定 CSV 与来源哈希清单。随附波长轴来自 F1520808 标定导出，PX6D 配置保留当前硬件身份绑定；实际光谱设备与此标定文件的对应关系仍须核实。更换设备须重新核对 `config/device.json` 与对应标定，不能套用旧设备的轴。安装脚本不安装硬件驱动。

采集数据、训练模型、用户设置和本机验收证据存放于 `userdata/`、`evidence/`，不随源码上传；本机原件继续保留。历史版本说明中的本地证据路径仅用于本机追溯。可选运行 `9FBG-Test.cmd` 检查 Python 测试。原 `frontend/`、HTTP 适配类及 Node.js 回归保留用于迁移对照和历史行为保护，均不参与正常启动；脉搏处理已迁移到 Python，使用原有源时间、频带、噪声定权与候选周期规则。

## 0.18.0 脉搏带通上下限输入

合成曲线下方新增“下限 / Hz”“上限 / Hz”两个输入框，默认 0.7～3 Hz。输入草稿保留原曲线与权重，点击“应用频带”才生效。合法范围为 0.1 ≤ 下限 < 上限 ≤ 8 Hz，并在有当前有效提峰率时检查上限；非法值显示中文原因，不改变已有状态。同值应用保留曲线，不重复采集。

改变频带会清除原带内噪声权重，必须重新明确无载并录制噪声；不自动采集、不发送参考或设备设置命令。设备原始采集、512 点坐标、寻峰算法与配置不变，频带仅作用于本页脉搏处理。重录完成后仍自动连续显示、沿用 FBG5 中心优先规则。

默认 3 s 预热与 120 ms 分段行为保持；较低下限延长预热，较高上限按每个真实源间隔检查滤波安全，过长间隔分段并提示降低上限。仍要求 ≥10 s 有效无载、≥7 s 预热后数据及 181/126 样本，60 s/12000 样本界限保留。候选周期仍只在所选频带与 0.7～3 Hz 的交集内判断，频带外的其他周期不会直接解释为心率。

界面显示当前实际频带、预热要求及候选判断范围。设置仅本页有效；刷新后回到默认频带并重新确认无载。兼容正在运行的连续九峰服务，不为这次更新重启设备。详见 [0.18.0 发布说明](RELEASE_NOTES_0.18.0.md)。

## 0.17.1 无负载录制的短时掉速修正

修复噪声录制刚过 2 秒、有效提峰率稍低于 20 Hz 就销毁本次采集并要求重录的问题。现场只读历史存在 2.016 秒内 39 帧、约 18.85 Hz 的有效输出，虽然较长时间接收/处理仍在约 25 Hz，旧门槛仍会触发。这里衡量的是已处理九峰的源时间吞吐，不等于设备物理新帧率。

噪声统计改为补足真实有效无载 ≥10 s、预热后带内数据 ≥7 s、原始有效样本 ≥181、带内样本 ≥126；四项都满足后才固定权重，较慢时自动延长，进度不提前显示完成。20 Hz 保留为候选周期资格；低率仍显示真实曲线，不给候选频率。120 ms 缺口分段、1 s 断流、60 s/12000 样本上限、失峰及参考/配置/算法/采集段门禁继续有效。没有补帧或更改设备采样请求、寻峰算法、FBG5 中心优先权重公式。

界面显示有效秒数和实际样本数，混合旧策略脚本时在采集前锁定。刷新脉搏页即可使用 0.17.1，无需为了本次修复重启正在采集的服务。详见 [0.17.1 发布说明](RELEASE_NOTES_0.17.1.md)。

## 0.17.0 固定权重曲线持续显示与界面优先刷新

明确确认无载、完成一次有效 10 s 噪声后，自动固定权重并持续显示合成曲线。无需贴手确认或再次开始；可随时把脉搏位置放在 FBG5 附近、移开，再放回。移动、预热、短暂缺帧和同源断流保留曲线历史与权重，曲线按真实源帧分段，预热段颜色较浅且不参与周期判断。主动暂停后仍须点击继续，参考、配置、算法、采集时段或有效通道失效仍需重采噪声。

默认开启“曲线优先刷新”，采集噪声和连续观察时暂停其他新版 9FBG 页面的大快照轮询、图表重画和实验状态刷新，后台设备采集、保存与训练继续。其他页显示暂停前快照并禁用依赖实时状态的操作，可点击恢复，获取新状态后再操作。隐藏、暂停、重置或中断会释放显示优先权，异常关闭页面后租约自动到期。旧工作台页也需刷新一次以加载此机制。

脉搏页改为小批量 100 ms 轮询，首次/恢复只读当前水位，不下载并丢弃整段历史；画布尺寸仅在大小或像素比变化时重设，无新点不重画，权重表仅在权重或噪声改变时更新。密集曲线保留各像素内真实极值及断点，周期频谱保持原时间与频率定义。兼容现有连续九峰服务，本次不重启已连接设备。详见 [0.17.0 发布说明](RELEASE_NOTES_0.17.0.md)。

## 0.16.0 无负载噪声定权 · FBG5 中心主路

操作员于 2026-10-16 明确确认 FBG5 离中心最近。本版移除笔头点压与人体贴稳学习步骤：记录一次有效 10 s 无负载噪声后，自动计算固定权重；将脉搏位置轻贴中心附近，确认接触并开始观察即可。

权重采用明确的中心优先噪声规则：50% 固定留给 FBG5，另 50% 在九路之间按脉搏带内噪声倒方差分配，全部非负、总和为 1。FBG5 因此至少占 50%，其他光栅不按编号推断空间距离。噪声只用于评估噪声大小，没有从无载数据推断机械响应的正负或灵敏度；这组显示融合权重不是按压或力模型。

测量期间权重不更新。允许自然微动，明显移动或短暂缺帧会清除当前周期判断并重新预热，恢复后自动继续观察；网络长时间中断需再次确认接触，保留同绑定权重。候选周期要求中心 FBG5 与合成信号的噪声比和相关性通过，不再要求所有辅助光栅都有相同强度的脉搏响应。参考、配置、提峰算法、采集时段或有效通道改变仍使本次噪声权重失效。

## 0.8.0 全谱 MLP＋GRU 与固定时长六维采集

当前稳定入口为 **0.8.0 源码开发版** `C:/光纤触觉/9FBG.lnk`，仍由独立 `.venv` 和 `9FBG-Dev.cmd` 启动。保留采集、训练、实机验证三个工作区，以及原有 `linear`、九维输入的小型 `mlp` 和历史文件；新增方法 `spectral_gru`，界面名称为“全谱 MLP＋GRU（六维力）”。本次为研究功能增量，不是物理按压精度验收或正式 EXE 发布。

全谱功能的可选 CPU 依赖需显式安装：

```powershell

.\9FBG-Dev.cmd
```

安装入口使用现有独立环境和 `requirements-ml.txt`，锁定 `torch==2.10.0+cpu`。本机已在 Python 3.14.1 64 位环境执行 CPU 前向、反向与子进程训练检查；其他机器仍须满足对应轮子的 Python/平台条件。日常启动不安装依赖、测试、打包或自动连接设备；未安装 PyTorch 时，旧采集和旧算法仍可使用。

新采集协议 `timed_wrench_v1` 在真实记录的 **25 Hz 光谱请求**下，先保留约 **1 s 采前无载**，再记录固定 **3 s 主按压**，随后继续保存卸载与恢复。3 s 由后端源帧与单调时间推进，页面刷新不会推进试次。接触点须始终保持在人工确认的位置，力度方向可以变化；正常轻按不要求达到旧协议的 3 N 或覆盖旧力箱。默认上限为扣除有效软件零偏后的三维合力 `sqrt(Fx²+Fy²+Fz²) ≤ 5 N`，不把力矩加入范数。超限仍保存真实读数并标记失败，不裁剪标签；软件记录不能保证采样间隙中的物理峰值。

首次无载必须人工明确确认。恢复阶段依据上一有效零偏、六轴噪声、三维合力、力矩、稳定时长及光谱恢复证据检查，默认稳定时长 0.8 s；阈值为可配置的研究起点。稳定非零按压不会被自动回零，恢复不足时继续等待或要求人工确认；确认也不能绕过残余载荷检查。每轮冻结真实原始谱逐点中位数 `S0[512]` 和六轴零偏，保留参考版本与源帧，之后更新不反写历史。

模型只接收 `intensity - S0` 的 **16 个真实连续源帧**：逐帧共享 MLP `512→128→64`，接单层单向 GRU（64 隐状态），以末帧状态输出 25 类位置和 `[Fx,Fy,Fz,Mx,My,Mz]` 六个有符号分量。各窗口隐藏状态重新置零，不按网页轮询组窗；六轴保持 PX6D 原点与方向，前三轴单位 N，后三轴单位 N·m。推理异步执行，不以 PX6D 真值或选中目标作为输入；重连、参考、轴或配置变化会清空历史并重新预热，未训练点不输出有效定位。

训练只读取已结束、四个原始文件及 manifest 哈希完整的会话。全谱模式默认累计选择可训练 A/B 来源，也可清空后明确选择子集；不兼容的样件、点阵、装夹、温度或采样/预处理定义须分开训练。划分按完整会话或试次及其共享无载来源固定保存，恢复帧被下一轮 S0 复用时也归入同组；新增数据不把旧验证组转成训练组。归一化与梯度更新只使用训练集合，C 批不参与拟合、调参或早停；数据不足会明确显示没有独立验证。六维同步使用 `timed_wrench_sync_v1`：左右力帧间隔不超过 60 ms、各端点距光谱时刻不超过 45 ms；最近帧仅供诊断。它仍是主机接收时间近似配对，设备延迟未知且未校正，不构成同步精度承诺。旧协议的 40/25 ms 规则保留。

CPU 训练独立运行，默认计算线程 2、批大小 32、Adam 学习率 0.001、迭代上限 100、早停耐心 10；参数可调整。采前记录到卸载恢复/基线检查完成期间，请求并等待训练进程确认保护暂停；用户暂停与采集暂停分别管理，采集结束不会解除用户暂停。暂停任务仍占用唯一训练名额，训练期间禁止删除或恢复来源。候选模型保存在 `userdata/spectral_models/<模型编号>/`，完整权重和元数据校验、原子保存成功后才显示 100%，需手动应用。

## 0.4.2 显式高分辨率等待与后台运行验证

0.4.1 的无载诊断通过后，操作员实际会话仍出现两路节拍同时降速。三轮九峰全部有效、力值在无载范围内，但光谱辅助进程接收节拍约 15.6 ms、六轴约 34 Hz，同步因此反复失败。这说明前一版有限时段验证不足以保证其他运行状态。

## 0.4.1 六轴独立读取与预采样诊断

修复六轴读取线程等待光谱拟合锁的问题。引导轮次收尾改由处理线程及显式操作执行，保留处理尾帧追赶与参考冻结规则；光谱拟合耗时不会再通过该收尾操作拖住 PX6D 下一次读取。

实机进一步定位到 Windows 等待粒度导致的轮询延迟：采集读取线程存活期间，Python 采集进程显式请求 1 ms 计时精度，退出线程时成对释放，失败会记录实际状态。光谱辅助进程的计时请求不代替本进程请求；该语义依据 [Microsoft timeBeginPeriod 文档](https://learn.microsoft.com/en-us/windows/win32/api/timeapi/nf-timeapi-timebeginperiod)。启动和离线回放不请求硬件采集计时。

预采样显示服务端实际的连续有效时长（目标 500 ms）、等待时长、重置次数和具体等待原因。超过 8 秒仍未取得合格预采样会结束失败轮、保留原始记录、不计入合格次数，并要求重新确认无载、手动标定。即使没有新帧，处理线程也检查超时；页面刷新和前端时钟不会推进采集阶段。

连续无载 ±0.1 N、同步间隔 40 ms/端点距离 25 ms、加载有效率 90% 等采集条件沿用，九峰算法、实际 512 点标定轴和固定身份配置不变。100 Hz 仍为设备读取请求，实际接收率与提峰处理率分别显示，不把显示跳过的帧计作成功提峰。无载诊断不构成真实按压、定位或力精度验收。

曝光、采样请求、会话条件、每点次数、上次预选点、光谱显示范围和分析选项修改后保存到 `userdata/settings.json`，下次启动恢复。保存采用校验及原子替换；无载确认、零点、参考授权、设备连接和进行中的轮次不保存为下次运行状态，启动仍不自动连接硬件。旧会话与模型保持原有内容和定义。

## 0.3.0 手动采集接口与研究反演（兼容保留）

下列分阶段手动采集接口保留兼容；0.4.0 GUI 使用上面的引导流程，分析与独立测试原则沿用。

保留光谱、九峰与六轴显示，新增“25 点标定与独立测试”工作区。连接仍默认仅显示；只有明确点击“建立记录会话”才创建 `userdata/calibration_sessions/` 下的新会话，不会自动开始真实按压或训练。

1. 接好光谱与 PX6D，按现有无载流程取得稳定的 9 峰。输入真实样件标识、批次 A/B/C、压头尺寸及固定条件，核对 25 点编号和方向。当前采用行列和归一化坐标，无毫米误差声明。
2. 操作员已确认压入时 PX6D Fz 更负；默认标签为 `F_press = −(Fz−Fz₀)`。原始六轴值及负号完整保留。安装或方向改变后应重新确认。
3. 选 P01～P25，每次独立按压前明确无接触并建立新基线。九峰稳定参考与服务端六轴 12 个不同帧、至少 400 ms 的中位数零点同时就绪后，才能开始试次。
4. 依次标记无接触预采样、加载、保持、移开、恢复、完成；建议预采样约 1～2 秒、缓慢加载约 3～5 秒、保持约 0.5～1 秒。加载与保持时冻结基线。有效且在空载噪声范围内的预采样用于无点位的噪声统计，原始阶段保留；非零接触预采样不冒充无载。中止或人工异常会排除整次试次，不删除原始文件。0～3 N 为初始方案，先逐步检查 0.5、1、2 N 响应和回零，未声明结构承载上限。
5. 结束会话后选择数据，先做少量点的诊断分析，查看九路波长漂移—力曲线、逐试次叠加、灵敏度、残差与保持状态。中心及四角试采不要求先凑齐 25 点。
6. 建模只选择 A+B 会话：A 组有无载和全部 25 点按压，B 组有无载及按压用于选择拒识阈值。线性加权最小二乘为默认主方法，同时可比较分段曲线及固定种子 `9→64→32→25 类＋1 路力` MLP。C 批不能提交建模，只在明确执行独立评估时使用。
7. A/B/C 以完整会话和试次隔离，A 拟合统计和模型，B 选阈值，C 独立评估；不逐帧随机拆分。报告包含已知点估力、联合估力、混淆、按力箱和会话统计、拒识比例及格距误差。该原则与 [scikit-learn 分组交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)一致。
8. 载入研究模型后，核对界面显示的模型样件及力定义，再明确无接触建立本次 FBG 测试参考；旧显示参考不会自动授权独立预测，切换模型后需重建。实时预测仅输入 9 个有符号波长漂移。PX6D 仅作独立真值对照，可断开；连接时独立建立服务端测试零点。无接触、定位不确定、无效和超范围分别显示，未接受估计不输出假确定点位。评估会话及已知的实时实验定义必须与模型的样件、坐标和力方向一致。

两路原始数据、逐峰完整结果和操作事件分别记录，按采集接收时间标注身份和阶段；保留单调时钟、流时段、原始包、基线、实际配置和 SHA256。训练表另存于 `userdata/analyses/<任务>/aligned_features.jsonl`，不覆盖原始文件。

离线分析先核对原始档案哈希，再逐个处理保存的原始光谱，包括在线显示队列跳过的帧。`frozen_identity_raw_replay_v1` 恢复采集时保存的固定窗口、身份锚点、完整配置和拟合种子，沿用原始局部背景高斯算法；只使用已经确认并生效的原参考及六轴零点，不根据未来数据重新归零。不安全或缺失的恢复证据明确拒绝。PX6D 采用有界缓存配对，原始数据和在线结果均保留。大会话显示当前会话补算条数。

同步接受精确接收时刻或同一时段左右插值，间隔上限 40 ms、两端距离上限 25 ms；保留实际最近样本距离，5 ms 只作为检查目标。插值的时间差为零不能冒充物理采样同步。当前设备无共同硬件时钟。

模型为版本化 JSON，核对来源摘要、参数、算法及配置；研究模型始终 `formal_ready=false`。本版没有代替操作员采集真实按压数据，也没有训练或认证现场模型。现有正式训练门仍要求真实无载/按压同批算法比较、实测漂移范围和审阅确认，不会因点击模型按钮而绕过。

## 实际设备边界

- BaySpec USB20BS SDK 返回 512 个原始 uint16 计数，**不返回实时波长轴**。使用独立保存并校验的 F1520808 厂商实际 Sense 导出标定轴。该轴非均匀，拟合使用每个实际波长值。当前物理对应、时间语义详见 `docs/DEVICE_AUDIT.md`。
- 本程序不扣背景、不平滑原始强度。DLL 内部处理未公开。平滑只可能用于粗定位；实际拟合用原始点，背景常数由拟合估计。
- 曝光和轮询等默认配置在 `config/device.json`；值来自已有设备配置和本次实测调整，不能用截图估波长。SDK 编程请求及换算值不冒充读回。请求轮询频率、收到的主机帧率、可证实的新设备帧率分别显示；协议缺少硬件帧号，真实新帧率保持未知，数值相同不删除。
- PX6D 独立读取六路 N / N·m 原值，未自动去皮或更改厂家校准。两路都保留原始数据和主机单调接收时间，匹配只接受受限左右括帧或精确接收时刻。主机接收时间近似对齐不等于物理曝光同步。
- 高斯窗口来自实际九峰及相邻峰中点，身份固定。按压漂移预留范围在真实按压数据确认前标记“未验证”，正式训练门会拒绝。
- 设备采用共享独占租约；同一硬件不能由多个端口/进程同时打开。
